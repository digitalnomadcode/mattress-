# VELORA

Рабочий магазин на Next.js 16, React 19, TypeScript и PostgreSQL (Prisma 7). Витрина, заявки и админка доступны на русском и казахском. Лендинг — /ru или /kk, каталог — /{locale}/catalog, корзина — /{locale}/cart, панель — /admin.

## Возможности

- Дизайн по брендбуку: кремовый, бежевый и тёмно-синий, векторные логотипы с русской/казахской подписью и локальные шрифты. Контакты: Instagram matt.resskz, WhatsApp и звонки +77058216103.
- Модели Luna 2601, Aria 2602, Vita 2603, Alba 2605, Oro 2606. Сохранены технические SKU и 12 размерных цен из пользовательского Excel.
- Верхняя CSS 3D-схема раскрывает слои при прокрутке. Выбор модели меняет состав; есть управление с клавиатуры и reduced motion. Это условная схема, не оцифрованная модель и не реальные фото.
- Корзина хранит SKU и количество в браузере. Сервер проверяет наличие и текущие цены, сохраняет заявку и ценовой снимок. WhatsApp открывает подготовленное сообщение только по нажатию покупателя.
- Авторизация администратора, роли OWNER / MANAGER / WAREHOUSE, отзыв доступа отключённого пользователя и ограничение частоты входа. Открытой регистрации нет.
- Админка: заказы, резервирование, поступления, продажи вне сайта, возвраты, исправления остатков с причиной, распределение неуточнённых 90 см, подсчёт по зонам, изменение названий/описаний/цен, контактов и условий получения, графики и Excel.

При подключённой БД витрина читает опубликованные активные варианты и остатки из PostgreSQL. Без DATABASE_URL доступен просмотр исходного каталога; создание заявок и админка требуют БД.

## Локальный запуск

Node.js 22.12–24, npm, Docker Compose. Проверено на Node.js 24.19.0 и PostgreSQL 17.

```sh
npm ci
npm run setup:local
docker compose --project-name velora-dev --env-file .env.local up -d --wait db
npm run db:generate
npm run db:deploy
npm run db:seed
npm run dev
```

setup:local создаёт случайные локальные секреты в игнорируемом .env.local с правами 0600 и сохраняет существующие значения. Docker хранит БД в именованном томе. Production-сборка: npm run build, затем npm start. Адрес по умолчанию — http://localhost:3000; NEXTAUTH_URL должен точно совпадать с адресом в браузере, включая протокол и порт.

В управляемой среде с конфликтующим Docker context используйте штатный сокет /var/run/docker.sock и инструкции runtime среды; не удаляйте Docker credentials/config.

### Первый владелец

В защищённых настройках процесса задайте ADMIN_EMAIL и ADMIN_PASSWORD (12–200 символов), затем выполните npm run admin:create. Пароль пока не задан, поэтому доступ владельца ещё не активирован. Пароль не отправлять в чат и не хранить в Git. Скрипт сохраняет scrypt-хеш и не печатает значения. Повторный запуск не меняет пароль или роль существующего аккаунта. После создания уберите ADMIN_PASSWORD из окружения.

Для приложения постоянно нужны DATABASE_URL, случайный AUTH_SECRET и точный NEXTAUTH_URL. DIRECT_DATABASE_URL — необязательное отдельное прямое подключение для миграций. Переменные перечислены в .env.example.

Если DATABASE_URL принадлежит существующей интеграции Vercel, задайте отдельный VELORA_DATABASE_URL для магазина. Он имеет приоритет в приложении и не изменяет старые подключения; DIRECT_DATABASE_URL задаёт прямое подключение для миграций. Интеграционные тесты отказываются запускаться с VELORA_DATABASE_URL, чтобы не обращаться к рабочему складу.

## Учёт

available = onHand − reserved. Новая заявка ничего не резервирует. Подтверждение резервирует, доставка один раз списывает товар и создаёт продажу. Отмена до доставки освобождает резерв. Для доставленного заказа нужен отдельный физический возврат после приёмки товара.

Начальный снимок импортирован через неизменяемые OPENING-движения: 89 известных SKU + 10 матрасов 90 см без распределения по Luna/Vita = 99. Распределение создаёт пару движений и сохраняет общий итог. Повторный seed не дублирует остаток и не перезаписывает правки. Исторические 25 продаж уже включены в начальный остаток; их цены неизвестны, поэтому в выручке они не учитываются. Подсчёт по зонам показывает расхождение, но не меняет SKU автоматически.

Миграции содержат SQL CHECK-ограничения и запрет изменения журнала. Операции транзакционные, с ключами повторного запроса и защитой от одновременного резервирования последней единицы. В production использовать только db:deploy; не применять reset/db push к рабочему складу.

## Проверки

```sh
npm run lint
npm test
npm run db:validate
npm run test:integration
npm run build
npm run typecheck
npm run test:store
```

Интеграционные и полные браузерные тесты создают случайную отдельную схему только в локальном PostgreSQL, очищают только её, не меняют рабочий склад и отказываются запускаться с внешним адресом БД. test:store сам поднимает временный production-сервер на 3100, использует временные учётные записи и проверяет заявку, подтверждение/доставку, повтор операции, CSRF, роли, отключённый аккаунт и Excel. Нужен Chromium: npx playwright install chromium или переменная CHROMIUM_PATH=/usr/bin/chromium.

После запуска обычного сервера: npm run test:smoke проверяет обе языковые версии, все модели, фильтры, цены и ширины браузера; npm run test:cutaway проверяет раскрытие пяти разрезов и reduced motion. Эти проверки не создают заказы. GitHub Actions проверяет сборку и операции на временном PostgreSQL.

## Перед публикацией

Production опубликован на https://mattress-umber.vercel.app с отдельной базой Neon. Применены три миграции, создан владелец, загружен исходный снимок склада: 99 шт. (89 распределённых и 10 нераспределённых). Перед реальной продажей сверить этот снимок с фактическим складом. Preview и production должны использовать разные базы. Временные ключи настройки не нужны работающему приложению.

Фотографии пяти моделей получены из папки владельца в Google Drive и добавлены в каталог и галереи; сопоставление и особенности отображения — docs/product-photos.md. Отзывы имеют честное пустое состояние, видео скрыты до получения материалов. Для Алматы и Астаны показаны ссылки на города: точные адреса и часы ещё не предоставлены. Неизвестные гарантии, нагрузка и происхождение не придуманы; подтверждённые значения можно заполнить в админке. Онлайн-оплаты нет. Для n8n события сохраняются в outbox, внешний webhook пока не подключён и ничего автоматически не отправляет. Render для текущей архитектуры не требуется.

Перед выпуском выполните npm run release:check в защищённом окружении релиза: проверка читает конфигурацию, миграции, доступ владельца и соответствие склада журналу. Локальный Docker URL не подходит для production; проверка без переменных намеренно завершается с NOT READY.
